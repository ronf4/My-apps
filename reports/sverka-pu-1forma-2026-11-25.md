## Что не соответствует (по важности)

### 1. Подчинённые объекты сделаны полями, а не реестрами
ТЗ: риски, дефекты, требования, бюджет, расходы, запросы на изменение, стейкхолдеры,
выгоды, команда — отдельные объекты «один ко многим» (O-02…O-19).
Факт: это блоки одиночных полей внутри одной карточки, и все скрыты.
В проекте можно записать только 1 риск, 1 дефект, 1 требование и т.д.
Это главный разрыв: переделывать в отдельные разделы или таблицы.

### 2. «Работа» (поток работ, O-20) не отделена от проекта
Нет отдельного раздела. Блок «РАБОТА» лежит внутри карточки проекта и скрыт.
Кнопки «Создать как работу» и порога 40 ч нет (A-29).

### 3. Статусная модель расходится
- Нет статуса P13 «В очереди на старт» и переходов P05→P13→P06.
- Нет возврата P07→P06 (из приостановки можно только «Прекратить»).
- Есть лишний переход P10 «Прекращён» → «Выполнение» («Возобновление»).
- Есть прямой переход «Выполнение → Архив», минуя приёмку и закрытие (P08/P09).
- Есть «Черновик → Инициация», минуя согласование P01 (и скрытый автопереход).
- Есть «Отклонить» из Черновика; в ТЗ отклонение только из P01.
- P05 «План на утверждении» → назад в P04 нет.
- Статусы «Отклонена» и «Архив» выключены (неактивны), но проекты в «Архиве» есть.
- Названия не по ТЗ: «P08 Закрытые» (в ТЗ «Закрытие»), «P09 Закрыть» (в ТЗ «Закрыт»).
- «Причина» обязательна только при отклонении из Инициации. При приостановке и
  прекращении не требуется (в ТЗ требуется).

### 4. Нет ни одного обязательного поля и ни одного поля «только чтение»
Из 249 полей обязательных 0, только для чтения 0. Значит:
- категорию, даты КТ, маржу, базовые даты можно править руками;
- заявку можно отправить пустой (условие P00→P01 не проверяется).

### 5. Автоматизации ТЗ не работают (данные это подтверждают)
По 34 проектам:
- Категория проекта — пусто у всех 34 (A-02 не сделан).
- Трудоёмкость = 0, интеграции = 0, подрядчик = «нет» у всех — значения по умолчанию,
  категорию считать не из чего.
- Поток — пусто у всех.
- Код проекта ПР-ГГГГ-NNN — поля нет (A-01).
- Спонсор проекта — пусто у всех (хотя подпись спонсора запрашивается).
- КТ-1, КТ-4, КТ-5, КТ-6 — даты пусты у всех, хотя проекты прошли эти статусы.
- Базовые даты начала/завершения — пусто у всех; блокировки после КТ-4 нет (A-05).
- RYG — пусто у всех (A-04).
- Дата подачи заявки, источник финансирования, обоснование — пусто у всех.
- Причина приостановки и дата пересмотра — пусто у всех 4 приостановленных (A-28).
- Расчёт себестоимости из таблицы «Карточка проекта» работает, но робот пишет
  ошибку «Факт часы НЕ записаны…» (сопоставление исполнителей не срабатывает).

### 6. Экраны ТЗ (Приложение В)
- Заявка (экран 1): отдельной формы с расчётом категории на лету нет.
- Карточка «Общее» (экран 2): плиток возраст/прогресс/маржа и списка обязательных
  документов нет; вкладки по обязательным документам не скрываются.
- Реестр портфеля (экран 4): есть, но нет плиток «Время цикла (медиана)»,
  «Старты : закрытия», «Загрузка отдела».
- Поток работ (экран 5): нет.
- Еженедельный обзор (экран 6): нет (A-30).

## Что сделать в первую очередь (первый этап ТЗ)
1. Довести статусную модель: добавить P13, P07→P06, убрать P10→Выполнение и
   Выполнение→Архив, сделать обязательными причины.
2. Включить обязательность полей заявки и «только чтение» для расчётных.
3. Сделать расчёт категории (A-02), код проекта (A-01), запись дат КТ при переходах.
4. Вынести «Работу» в отдельный раздел с 7 полями и порогом 40 ч.
5. Дополнить портфель метриками потока и сделать еженедельный обзор.
6. Заполнить справочник «Методология реализации», починить запись факт-часов.
Потом второй этап: вынести риски, дефекты, требования, бюджет и прочее в реестры.
